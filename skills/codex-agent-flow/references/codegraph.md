# CodeGraph 的适用条件与测量

调用链、错误传播、受影响调用者/测试等跨文件问题可用一次聚焦的 source + call path
替代多轮搜索；已知单文件定位未必更省。遵循仓库的 CodeGraph 优先、status/sync 规则；
无索引时不为测量擅自创建。结果不全再回退源码搜索；输出太大先收窄查询，图过期按项目规则更新。

比较时从同一 commit 做同一多文件追踪任务：A 用 CodeGraph 聚焦查询，B 用 `rg` 和按需读
文件。记录总 input/cached input、响应轮数、工具输出大小、遗漏调用者、耗时与正确性。
不能只比较返回字符数或把调用次数差异当成因果；缓存与非缓存输入也不等价于相同成本。
完整实验控制见 [ab-evaluation.md](ab-evaluation.md)。

不要用工具调用次数、搜索次数或返回字符数直接推断 token 节省。只有同任务对照通过相同
验收，且完整记录上下文、工具输出和用量后，才能判断是否值得采用。
