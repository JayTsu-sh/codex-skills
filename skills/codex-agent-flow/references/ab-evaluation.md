# A/B 对照：先隔离流程，再谈模型

用量采集和字段口径见 [usage.md](usage.md)。

1. 选 3 类任务：小 bug、跨模块改动、设计调研。每类至少 2 个样本；资源允许时每个
   任务 A/B 各重复 2–3 次，报告中位数和范围。初试可先一对，但不能据此宣称普遍收益。
2. 每对从同一干净提交开始，使用相互独立的临时 worktree，明确指定各自分支/目录，
   避免 tape-rs 的接续规则把两组带回正式工作树。当前未提交实现不要 reset、复制覆盖
   或纳入基线。若任务依赖未提交内容，应先制作双方完全相同的受控快照，再开始实验。
3. 两组相同 Codex 版本、模型、推理档位、权限、工具/skills 清单、依赖、规则、任务文字、
   验收测试和超时。每组新会话，不提供另一组答案。记录这些条件和基线提交。
4. A 提示词说明“不使用 codex-agent-flow skill，按原有工作方式完成”；B 在相同任务前
   加 `$codex-agent-flow`。其余限制一致。A 中仍保留同样的 skill 清单，避免目录差异混杂。
   核实 A 没读取该 skill，B 确实读取；若触发其他流程或自动多代理，记录为混杂因素。
5. 交替 A→B / B→A 执行。Rust target 缓存和模型前缀缓存会影响顺序；保持可比的构建
   缓存条件，记录冷/热状态，不删除共享 target 或声称能强制清空服务端缓存。
6. 每组跑完同样验收。失败、漏测、返工、额外人工提示都记录并计入任务总成本；相同
   的外部验证开销单列。通过质量门槛后，再比较 token、响应次数和实测端到端耗时。

可选 headless 启动形式（替换目录、模型及任务文件）：

```bash
codex exec -C /absolute/path/to/trial-A -m '<同一模型>' \
  -c 'model_reasoning_effort="high"' --sandbox workspace-write \
  --json -o /tmp/trial-A-final.txt - < /tmp/task-A.txt > /tmp/trial-A-events.jsonl
```

B 同样启动，替换为 B 目录、B 任务文件和不同输出路径。任务文件明确指定本轮实验分支
与目录，不使用远程主机/真实设备，不 push。模型必须是本机可用且用户选定的同一模型。
`workspace-write` 不为实验降低安全门槛；本机信任或依赖限制导致失败时，两组同样处理。
是否已运行实验以对应产物为准；本文是操作方法，不声明当前实验完成情况。

| 记录项 | A | B |
|---|---|---|
| 基线提交 / 模型 / effort / 版本 | | |
| 验收通过数、漏项、人工修正次数 | | |
| input_tokens | | |
| cached_input_tokens | | |
| uncached_input_tokens | | |
| output_tokens（含 reasoning） | | |
| reasoning_output_tokens（输出子集） | | |
| cache_write_input_tokens（如报告） | | |
| responses / average_input_tokens | | |
| 端到端耗时、构建冷/热条件 | | |
| warnings、子代理及接力会话是否齐全 | | |

单项下降比例为 `(A - B) / A`，A=0 时不计算。可以预先把“通过同样验收，原始 total
中位数降低至少 20%，非缓存输入/输出无明显恶化”定为试验目标；20% 是你可修改的
判定阈值，不是已经测出的收益。缓存输入下降但高价类别上升时，不能声称省钱。
如果使用 API，按测试当日该模型的真实账单/官方价格核算各类别；订阅额度变化另记，
不使用任意权重推导套餐消耗。同样留意时间与人工负担，避免 token 降低却更难交付。

若仓库要求读取长交接，短 state 不能自行替代。要测试“短入口 + 按需历史”，单独变更新旧
接续入口并保留完整历史、设备状态和授权，作为另一实验变量。收益不足时依据数据逐项试验：
入口长度、成功日志、轮询、查询批处理或重复调研；代理拆分、模型路由、检查缓存分别评估。

专门测委派隔离时，一般使用上下文等价的新根会话；若研究长历史隔离，才保留历史差异
并声明为变量。记录 worker 自身用量和工具输出大小，用根会话总量比较端到端成本。
单次或不同 effort 的结果只作方向性证据。
