# 长任务与 worker 接续

委派分工按 SKILL.md 执行。这里处理长任务的生命周期和上下文隔离，不要求为每阶段新建代理。
相关小修复复用知情 worker；独立任务且旧上下文大多无关时才新建。客户端支持时只传必要
turn/context，避免继承整个长聊天；否则在短简报中重述必要事实。遵循仓库隔离方式，
不为本流程额外创建 clone、提交、清理或复制凭据。

## 等待与恢复

优先原生完成通知。只有轮询时保持一次活动执行，用宿主允许的有界等待（通常不超过
60 秒），或推进独立工作。等待本身不是模型推理，反复唤醒分析才增加开销；不虚构通知能力。
测试由确定性进程执行，worker 持有其结果，无需另开模型持续盯守。

未完成任务保留 PID/session ID、命令、日志与实际状态；不能 detach 后宣称完成。
[本地运行器](local-checks.md) 是前台包装器，不是持久远程任务管理器。已有授权硬件流程
继续使用专用超时、检查点和停止方式，不经通用 timeout 包装。

短 state 约 60 行为目标：目标/验收；工作树/分支/base/脏文件；决策和来源；已完成变更；
与代码状态对应的验证命令/结果/日志；负责人及活动任务；授权/设备限制；未决问题；下一步。
使用事实和指针，不追加流水账；仓库要求更长交接时照办，结构变更另提。

主线程仍保留已有历史并因协调增长，worker 也消耗用量。到安全边界需要压缩或换主线程时，
读 [context-growth.md](context-growth.md)，恢复时重新核对 Git 和活动任务。

测委派隔离效果时，按 [A/B 对照](ab-evaluation.md) 设计实验；不要把生命周期管理本身
当成节省证明。官方说明：[子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents)。
